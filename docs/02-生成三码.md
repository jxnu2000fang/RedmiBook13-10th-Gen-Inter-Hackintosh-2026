# 02 · 生成你自己的三码（必读）

> **这一步的意义：** 让 Apple 服务器认为「这台 Mac 是独一无二的」。本仓库把所有三码清空了，你要做的是生成一套**只属于你**的值填回去。
> **不做会怎样：** 能开机，但 App Store 下载失败、iCloud 登不上、iMessage/FaceTime 无法激活。
> **填错会怎样：** 如果填了网上抄来的三码（包括本仓库作者的原始值），多台机器共用同一套身份，会被 Apple 风控标记，**这才是真正会导致 Apple ID 被封的操作**。

---

## 一、四个字段分别是什么

| 字段 | OpenCore 位置 | 含义 |
|------|---------------|------|
| `SystemSerialNumber` | `PlatformInfo > Generic` | 机器序列号，12 位，App Store / iCloud 主要看这个 |
| `MLB` | `PlatformInfo > Generic` | 主板序列号（Main Logic Board），17 位，iMessage/FaceTime 必需 |
| `SystemUUID` | `PlatformInfo > Generic` | 硬件 UUID，格式 `XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` |
| `ROM` | `PlatformInfo > Generic` | 6 字节数据，通常取网卡 MAC 地址 |

> 本配置 `PlatformInfo > Automatic = true`，所以 OpenCore 会用 `Generic` 段自动生成整套 SMBIOS。
> `DataHub` 与 `SMBIOS` 两段里的同名字段本仓库也一并清空了——它们在 `Automatic = true` 时不会被采用，但**如果你哪天把它改成 `false`，这些字段就会生效**，所以清空是双保险。

---

## 二、机型必须匹配

本配置的 `SystemProductName` 是 **`MacBookPro16,4`**。

生成三码时**必须**选同一个机型，否则序列号与 SMBIOS 不匹配，iServices 依然会失败。

> 如果你想换机型：`MacBookPro16,2`（13 寸四雷雳口）或 `MacBookPro16,3` 也是 Comet Lake 平台的合理选择，但换机型需要整套 SMBIOS 一起换，且可能影响电源管理。新手建议就用 `MacBookPro16,4` 不动。

## 三、方法一：OCAT（图形界面，推荐）

[OCAT](https://github.com/ic005k/OCAuxiliaryTools) 是跨平台的 OpenCore 配置编辑器，内置三码生成。

1. 下载并打开 OCAT，用它打开 `EFI/OC/config.plist`。
2. 左侧进入 **`PlatformInfo` → `Generic`**。
3. 右上角「机型」下拉里确认是 `MacBookPro16,4`。
4. 点击 **「生成」**（有的版本叫 `Generate` / 骰子图标），会一次性填好序列号、MLB、SystemUUID。
5. `ROM` 需要手动填：先在终端执行 `ifconfig en0 | grep ether` 拿到本机网卡 MAC（形如 `5c:80:b6:9d:40:f4`），去掉冒号得到 12 位十六进制 `5c80b69d40f4`，在 OCAT 里把 `ROM` 的类型设为 **Data**，值填这 12 位。
6. `Command + S` 保存。

OCAT 左下角会提示配置是否通过校验，有红色错误要先解决。

## 四、方法二：GenSMBIOS（命令行）

```bash
# 1. 下载
cd ~/Downloads
git clone https://github.com/corpnewt/GenSMBIOS
cd GenSMBIOS

# 2. 安装 MacSerial（首次需要，选 1）
./GenSMBIOS.command
#    输入 1 → 回车，等待下载完成

# 3. 生成三码（选 3）
./GenSMBIOS.command
#    输入 3 → 回车
#    机型输入：MacBookPro16,4 → 回车
```

输出形如：

```
Type:         MacBookPro16,4
Serial:       C02XXXXXXXXX
Board Serial: C02XXXXXXXXXXXXXXX
SmUUID:       XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX
```

对应关系：

- `Serial` → `SystemSerialNumber`
- `Board Serial` → `MLB`
- `SmUUID` → `SystemUUID`
- `ROM` → 你的网卡 MAC（同上，12 位十六进制，Data 类型）

## 五、怎么判断生成的序列号"能用"

生成完别急着登录，先查一下：

打开 <https://checkcoverage.apple.com>，输入你的序列号：

| 查询结果 | 含义 | 建议 |
|----------|------|------|
| 「无法验证此序列号的购买日期」/ 提示需要提供购买凭证 | 数据库里没有这台"设备" | ✅ 可用 |
| 显示具体的机型、保修到期日、甚至已激活 | 撞上了真实在用的机器 | ❌ 重新生成，不要用 |
| 提示序列号无效 | 格式或校验位不对 | ❌ 重新生成 |

MacSerial 生成的序列号有较大概率落在"未注册"区间，但**不是百分百**，尤其是热门机型。多生成几次，挑一个查询不到保修信息的。

## 六、关于 Apple ID 被封的真实风险

这是很多人分享 EFI 时忽略的地方，值得单独说清楚：

### 什么情况会出事

1. **多人共用同一套三码**（最常见）
   作者的 EFI 原样打包上传，几十个人下载后都用作者的序列号登录 iCloud。Apple 侧看到同一硬件标识从几十个不同 IP、不同地理位置登录，会判定为账号异常。后果从「iMessage 激活失败」到「Apple ID 被锁定，需改密码并申诉解封」。

2. **抄了真实在保机器的序列号**
   序列号本身是有效的、有保修记录的，等于冒用他人设备身份。这种情况被处理的概率更高。

3. **同一套三码在实体机和虚拟机里同时登录**
   哪怕只有你自己两台设备，同一身份并发登录也会触发风控。

### 本仓库做了什么来规避

- `SystemSerialNumber`、`MLB`、`SystemUUID`、`ROM` 四组值全部置空，`DataHub` / `SMBIOS` 段的副本同样清空；
- 作者原始三码在仓库里**不存在**（可自行 `grep -r` 全仓库验证）；
- `AppleALC.kext` 的 `Comment` 字段里原本带有作者用户名，已一并中性化；
- 文档明确要求使用者生成独占三码。

### 你自己还要注意

- **用备用 Apple ID。** 黑苹果登录 iCloud 本身就有账号风险，别拿你主力账号（绑着银行卡、照片、备忘录的那个）去试。
- **开启两步验证。** 万一被锁，有恢复渠道。
- **不要频繁改三码。** 短时间内同一账号下设备身份反复变化，同样会被标记。
- **iMessage/FaceTime 不是必须的。** 如果只是想日常用，不激活 iMessage 反而最安全。

## 七、填完之后

1. `plutil -lint EFI/OC/config.plist` 确认没有语法错误；
2. 开机进 OpenCore，先 `Reset NVRAM`；
3. 进系统后 `system_profiler SPHardwareDataType` 确认序列号是你自己生成的那串；
4. 先只登录 App Store 试下载一个免费应用，正常了再考虑 iCloud。
