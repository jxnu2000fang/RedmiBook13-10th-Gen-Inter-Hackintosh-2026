### 4.4 音频 ⭐ 本包的核心改动

| Kext | 版本 | 作用 |
|------|------|------|
| `AppleALC.kext` | 1.9.9（定制） | 声卡驱动，`layout-id = 101`，**引脚配置已修正** |
| `VerbStub.kext` | 1.0.4 | 声卡动词注入，配合 `boot-args` 的 `alctsel=1 alcverbs=1` |

#### 改了什么

`AppleALC.kext/Contents/Info.plist` 的
`IOKitPersonalities → as.vit9696.AppleALC → HDAConfigDefault[663] → ConfigData`
中，节点 `0x21`（耳机口）的四条 Pin Configuration 动词被改写：

| 动词 | 原值 | 新值 | 含义 |
|------|------|------|------|
| `0x71C` (byte0) | `20` | `50` | 关联序号 |
| `0x71D` (byte1) | `14` | `10` | 关联组 |
| `0x71E` (byte2) | `21` | `2B` | 连接类型 `0x1` → `0xB` |
| `0x71F` (byte3) | `03` | `02` | 端口/位置 |

组装成 32 位引脚配置：**`0x03211420` → `0x022B1050`**。

按 Intel HDA Pin Configuration 格式解码：

| 位段 | 字段 | 原值 | 新值 |
|------|------|------|------|
| 31:30 | Port Connectivity | `00` Jack | `00` Jack |
| 29:24 | Location | `0x03` | `0x02` |
| 23:20 | Default Device | `0x02` HP Out | `0x02` HP Out |
| 19:16 | **Connection Type** | `0x1` 1/8" 耳机口 | **`0xB` Combination 组合口** |
| 11:8 | Default Association | `0x4` | `0x5` |

**关键就是 `0x1 → 0xB`。** RedmiBook 13 只有一个 3.5 mm 口，是耳机+麦克风的四段组合口。按普通耳机口配置时，macOS 的插孔检测拿不到正确的设备类型，这条通路就不会被启用，于是只有内置扬声器出声、插耳机没反应。改成组合口后，插拔检测正常，耳机与扬声器自动切换。

`WakeConfigData` 保持 `01470c02`（节点 `0x14` 扬声器 EAPD 使能），未改动。

> 该条目的 `Comment` 字段原本带有作者的用户名前缀，已在中性化为
> `Realtek ALC256 (3246) for Xiaomi RedmiBook 13 (TIMI TM1921)`。
> `Comment` 只是元数据，AppleALC 匹配只认 `CodecID`（`283902550`）与 `LayoutID`（`101`），不影响功能。

#### 如果你换了机型

`0x022B1050` 是**按本机 codec 实测**得出的。若你的 ALC256 是独立的耳机口（非组合口），这个值反而会让耳机失效。判断方法：插上耳机后在「系统设置 → 声音 → 输出」里看有没有 `Headphones` 设备；没有就说明引脚定义不匹配，需要按你自己的 `codec dump` 重新计算。

#### 包内还带了 3 个实验变体（可选，不用管）

`HDAConfigDefault` 里除了 `LayoutID = 101`（生效中），还有作者调试时留下的三条同 codec 的变体：

| LayoutID | 思路 |
|----------|------|
| `102` | 耳机与扬声器共用 DAC0（沿用 OEM 引脚） |
| `103` | 耳机共用 DAC0，`0x21` 按 HP Out 类型 |
| `104` | 耳机走 DAC1，`0x21` 按 HP Out 类型 |

它们**不会被加载**（`config.plist` 注入的是 `101`）。如果你的机器插孔形态与本文描述不同、101 怎么调都不出声，可以把 `layout-id` 依次改成 `102` / `103` / `104` 试，改完 `Reset NVRAM` 重启。三条都不行就说明要按你自己的 codec 重算。

> 这三条条目的 `Comment` 原本带有作者用户名，已一并去除前缀，其余内容未改动。

## 六、与原始 EFI 的差异

| 项目 | 原始 | 本仓库 | 原因 |
|------|------|--------|------|
| `SystemSerialNumber` / `MLB` / `SystemUUID` / `ROM` | 真实值 | 已清空 | 防止多人共用同一身份导致 Apple ID 风控 |
| `DataHub` / `SMBIOS` 中的序列号副本 | 真实值 | 已清空 | 双保险，防止 `Automatic` 改为 `false` 后泄露 |
| `AppleALC.kext` 的 `Comment` 字段 | 含作者用户名 | 已中性化 | 去除个人信息，不影响功能 |
| `EFI/Microsoft`（27 MB） | 存在 | 已剔除 | 微软专有引导文件，与黑苹果无关 |
| `EFI/Boot/win10bootx64.efi` | 存在 | 已剔除 | 同上 |
| `config.plist.bak-*`（8 个） | 存在 | 已剔除 | 历史备份，含旧序列号，无使用价值 |
| `Kexts-AppleALC.old-*` / `.broken-*`（6 个目录） | 存在 | 已剔除 | 临时回滚目录，纯冗余 |
| `OC/.backup-20261029-*`（3 个隐藏目录） | 存在 | 已剔除 | 修声卡时的回滚点，含旧引脚配置 |
| 未启用的 kext（48 个） | 存在 | 已剔除 | 避免误启用导致冲突（如 FakeSMC 与 VirtualSMC 并存） |
| 未启用的 ACPI（20 个） | 存在 | 已剔除 | 同上 |
| 未启用的 `Kernel > Add`（59 条） | 存在 | 已移除条目 | 保持配置与文件一一对应 |
| 未启用的 `ACPI > Add`（20 条） | 存在 | 已移除条目 | 同上 |
| 未引用的 Drivers（15 个）/ Tools（5 个） | 存在 | 已剔除 | 减小体积、减少误用 |
| **除上述以外的所有配置项** | — | **未改动** | 保持与作者机器完全一致的启动行为 |
| **所有 kext 二进制** | — | **未改动** | 原样分发，未经重新编译 |

体积 92 MB → 约 35 MB。`AppleALC.kext/Contents/Info.plist` 除 `Comment` 字符串外，`ConfigData` 保持作者修改后的最新状态（即耳机可用的版本）。
