# 04 · 故障排查

> 排查顺序永远是：**先确保能进系统，再修单项功能**。进不去就先回滚，别在坏掉的系统上改配置。

---

## 1. 根本进不去 OpenCore 菜单

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 开机直接进 Windows | EFI 启动项顺序不对 | BIOS 里把 `OpenCore` 调到第一位；或进 BIOS 手动选 `EFI/BOOT/BOOTx64.efi` |
| 黑屏，风扇转 | `OpenRuntime.efi` 没加载 / EFI 分区文件不完整 | 检查 `EFI/OC/Drivers/OpenRuntime.efi` 是否存在；重新完整复制一遍 |
| 出现 `OC: Failed to load configuration` | `config.plist` 语法错 | 在 macOS 上跑 `plutil -lint config.plist`，用 ProperTree 打开另存修复 |
| 花屏或分辨率异常 | `Resources` 主题资源与 `OpenCanopy` 版本不匹配 | 临时把 `Misc > Boot > PickerMode` 改成 `Builtin`（文本菜单），或删掉 `Resources` |

**Secure Boot 必须关闭。** 小米/红米笔记本的 BIOS 里通常叫 `Secure Boot`，设为 `Disabled`。部分机型需要先设 BIOS 密码才能改这一项。

## 2. 卡在 Apple Logo 或进度条

先按 `Command + V` 进啰嗦模式（本配置 `debug=0x100`，本来就会输出日志），看最后几行卡在哪：

| 卡住的位置 | 大概原因 | 处理 |
|-----------|----------|------|
| `apfs_module_start` | NVRAM / RTC 问题 | 菜单里 `Reset NVRAM`；检查 `SSDT-AWAC.aml` 是否加载 |
| `AppleIntelPCHC` / `IOACPIFamily` | ACPI 补丁与你的 DSDT 不匹配 | 只保留 `SSDT-PLUG`、`SSDT-EC-USBX-LAPTOP`、`SSDT-PMC` 测试，逐个加回 |
| `Waiting for root device` | 硬盘没被识别 | 检查 NVMe 是否被 `SATA-unsupported` 类补丁影响；本包未含该 kext |
| `IOConsoleUsers: gIOScreenLockState 3` 后黑屏 | 显卡 framebuffer 不对 | 本包已注入 `0x3E9B0000`，同平台机型若不同需按你的核显改 |
| 无限重启 | 内核 panic | 啰嗦模式拍照，第一行 `panic` 后面的 kext 名就是元凶 |

**通用急救：** 菜单里选 `Reset NVRAM` → 重启 → 若还不行，把 `boot-args` 加上 `-x`（安全模式）看能否进系统，能进就说明是某个 kext 的问题。

## 3. 耳机没声音 / 插拔不自动切换

**正常情况下本包是好的**（内置扬声器与耳机都出声，插拔自动切换）。如果你遇到了问题，按下面顺序查。

### 3.1 先确认三件事

```bash
# ① layout-id 必须是 101（0x65）
ioreg -l | grep -o 'layout-id" = <[0-9a-f]*>' | head -3
# 期望看到 <65000000>

# ② AppleALC 必须已加载
kmutil showloaded | grep -i applealc
# 期望：as.vit9696.AppleALC (1.9.9)

# ③ 插上耳机后看输出设备
system_profiler SPAudioDataType | grep -A2 "Output Source"
# 期望：Output Source: Headphones（未插时是 Internal Speakers）
```

### 3.2 最常见的原因：AppleALC 被换成了官方原版 ⚠️

本包的耳机修复**不在** config 里，而在 `AppleALC.kext/Contents/Info.plist` 的 `HDAConfigDefault` 里（`LayoutID = 101` 那一条的 `ConfigData`）。

所以：

- 如果你用 Hackintool / OCAT / 任何工具**升级了 AppleALC**，这个修正会被官方原版覆盖，耳机立刻失效；
- 如果你从别处下载了"更新版"的 AppleALC 替换进来，同样失效；
- 恢复方法：换回本仓库 `EFI/OC/Kexts/AppleALC.kext` 原文件。

**升级 AppleALC 之前，先把本仓库的 `AppleALC.kext` 备份出来。**

### 3.3 自己核对修复是否还在

打开 `EFI/OC/Kexts/AppleALC.kext/Contents/Info.plist`，搜 `HDAConfigDefault`，找到 `LayoutID` 为 `101` 的条目，看 `ConfigData` 里这段字节：

```
... 01 47 0c 02 ... 02 17 1c 50 02 17 1d 10 02 17 1e 2b 02 17 1f 02 ...
```

注意 `02 17 1c 50` 这一组。**如果看到的是 `02 17 1c 20 ... 02 17 1d 14 ... 02 17 1e 21 ... 02 17 1f 03`，说明是旧版（耳机无声）。**

### 3.4 原理（想自己改的人看这里）

耳机节点 `0x21` 的四条 Pin Configuration 动词组装成 32 位值：

| 字节 | 动词 | 含义 |
|------|------|------|
| `02 17 1c XX` | `0x71C` | byte0 |
| `02 17 1d XX` | `0x71D` | byte1 |
| `02 17 1e XX` | `0x71E` | byte2（含 Connection Type） |
| `02 17 1f XX` | `0x71F` | byte3 |

`02 17 1e 21` → byte2 = `0x21`；`02 17 1e 2b` → byte2 = `0x2B`。

32 位引脚配置 = `byte3 byte2 byte1 byte0`：

- 旧：`03 21 14 20` = `0x03211420`，Connection Type（19:16 位）= `0x1` → 1/8" 耳机口
- 新：`02 2B 10 50` = `0x022B1050`，Connection Type = `0xB` → **Combination 组合口**

RedmiBook 13 只有一个 3.5 mm 口，是耳机+麦克风的四段组合口。按普通耳机口配置时 macOS 的插孔检测拿不到正确设备类型，这条通路就不启用，于是只有扬声器出声。

### 3.5 换了机型怎么办

`0x022B1050` 是按本机 codec 实测得出的。如果你的机器是**独立耳机口**，这个值反而会让耳机失效，需要按自己的 codec 重算：

1. 用 `HdaCodecDump` / Hackintool 导出你的 codec；
2. 看节点 `0x21`（或其它耳机节点）的 `Pin Default` 原始值；
3. 依 Intel HDA 规范重新拼 32 位值，拆成 `0x71C`~`0x71F` 四条动词；
4. 替换 `ConfigData` 里对应的字节；
5. `plutil -lint` 校验后重启。

改不动也没关系——用外置 USB 声卡（几十元）是省事的选择。

## 4. Wi-Fi 列表里没有接口

`AirportItlwm` 走的是第三方实现，**不会**自动出现在原生 AirPort 界面里。

1. 先确认 kext 已加载：`kmutil showloaded | grep -i itlwm`
2. 系统设置 → 网络 → 看是否有 `Wi-Fi` 接口。没有的话点左下角 `+` 手动添加。
3. **版本必须匹配系统版本**：`AirportItlwm 2.1.0` 是 Monterey 专用。升到 Ventura 会直接失效，需换对应版本。

---

## 5. 蓝牙打不开

Monterey 下 Intel 蓝牙需要三个 kext 同时在场且顺序正确：

```
IntelBluetoothFirmware.kext
IntelBluetoothInjector.kext
BlueToolFixup.kext        ← 少了这个，Monterey 上蓝牙开关是灰的
```

`BlueToolFixup` 必须排在 `IntelBluetoothFirmware` **之后**。顺序在 `config.plist > Kernel > Add` 里调整，改完 `Reset NVRAM`。

## 6. 电池图标显示叉 / 不显示百分比

- 确认 `SMCBatteryManager.kext` 与 `ECEnabler.kext` 都已加载（`kmutil showloaded | grep -i smcbattery`）；
- 部分机型 EC 字段名不同，需要在 `SSDT-EC-USBX-LAPTOP.aml` 里按你的 DSDT 补 `_BST` / `_BIF`；
- 修完进「系统设置 → 电池」看是否有数据。

---

## 7. 亮度调不了

1. `SSDT-PNLF.aml` 必须加载；
2. `WhateverGreen` 的 `enable-backlight-registers-fix` 本包已置 `1`；
3. 快捷键没反应但系统设置里能拖滑块 → 是 `BrightnessKeys.kext` 的键位与你键盘的 Fn 组合不符，属正常，先用设置面板调。

## 8. App Store 登不上 / iMessage 提示联系客服

99% 是三码问题，按顺序查：

1. `system_profiler SPHardwareDataType` 看序列号是不是空的 → 回 [02-生成三码.md](02-生成三码.md)
2. 序列号是你自己生成的吗？如果是抄来的（包括作者原始值），立刻换掉；
3. `MLB` 是否 17 位？`SystemUUID` 格式是否 `8-4-4-4-12`？
4. `ROM` 是否 6 字节（12 位十六进制）Data 类型？
5. 改完必须 `Reset NVRAM` 重启，否则旧身份还在缓存里；
6. 仍不行，换一个序列号重新生成（有可能撞上了已注册设备）。

**如果已经被锁：** 去 <https://iforgot.apple.com> 重置密码，通常能解锁；同时停止用该账号在黑苹果上登录。

## 9. 从零安装 macOS 12

本仓库只提供**已有系统**的 EFI，不含安装镜像。

1. 用另一台 Mac 制作安装 U 盘（`createinstallmedia`，16 GB 以上 U 盘）；
2. 把本仓库的 `EFI` 放进 U 盘的 EFI 分区（替换 U 盘里原有的）；
3. 生成三码并填入 U 盘上的 `config.plist`；
4. 从 U 盘启动 → 进 macOS 安装器 → 磁盘工具抹盘（APFS / GUID）→ 安装；
5. 安装过程中会重启 3–4 次，每次都要手动选回 U 盘或安装分区；
6. 装完后把 U 盘的 `EFI` 复制到硬盘的 EFI 分区，之后才能脱离 U 盘启动。

## 10. 怎么收集日志

```bash
# 内核扩展加载情况
kmutil showloaded | grep -Ei "lilu|virtualsmc|whatevergreen|applealc|itlwm|voodoo"

# 启动参数
nvram boot-args

# 硬件概览
system_profiler SPHardwareDataType SPDisplaysDataType SPAudioDataType

# OpenCore 日志（需在 config 里把 Misc > Debug > Target 设为 0x0B 并写入文件）
# 日志会出现在 EFI 分区根目录的 opencore-YYYY-MM-DD-HHMMSS.txt
```

提 issue 时请附上：机型、系统版本、卡住的截图或日志末尾 20 行、你改过什么。

---

## 出问题时的第一原则

**先回滚，再研究。** 备份的 EFI 拖回去，机器能开机，你才有排查的余地。在进不去的系统上折腾配置是最浪费时间的事。
